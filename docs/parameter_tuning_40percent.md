#### 2.1.1 平均リンク距離の算出方法

**データソース**: `config/topology/koriyama_topology.txt`

トポロジーファイルのLINK行から全リンクの距離を抽出し、算術平均を計算。

```
LINK形式: LINK <from> <to> <capacity> <distance> <weight>
例: LINK 0 1 4 1234.5 6.789
```

**算出式:**
```
平均リンク距離 = Σ(各リンクの距離) / リンク数
              = 584,700 m / 600
              = 974.5 m
```

**算出スクリプト例:**
```bash
# トポロジーファイルからリンク距離を抽出して平均を計算
grep "^LINK" config/topology/koriyama_topology.txt | \
  awk '{sum += $5; count++} END {print "平均リンク距離:", sum/count, "m"}'
```

### 2.2 経路統計（ダイクストラ法で計算）

| 項目 | 値 | 導出方法 |
|------|-----|---------|
| サンプル数 | 24,310ペア | 221×220÷2 |
| 平均経路距離 | 6,978.4 m | 全ペア最短経路の平均 |
| 平均ホップ数 | 7.89 hops | 全ペア最短経路のホップ数平均 |

#### 2.2.1 平均経路距離・平均ホップ数の算出方法

**算出手順:**

1. トポロジーファイルからグラフを構築（221ノード、600リンク）
2. 全ノードペア（無向グラフとして扱う）に対してダイクストラ法を実行
3. 各ペアの最短経路距離とホップ数を記録
4. 算術平均を計算

**計算対象:**
```
全ノードペア数 = C(221, 2) = 221 × 220 / 2 = 24,310 ペア
```

**算出式:**
```
平均経路距離 = Σ(各ペアの最短経路距離) / ペア数
            = 169,654,724 m / 24,310
            = 6,978.4 m

平均ホップ数 = Σ(各ペアの最短経路ホップ数) / ペア数
            = 191,842 hops / 24,310
            = 7.89 hops
```

**算出アルゴリズム（疑似コード）:**
```python
def calculate_path_statistics(topology):
    nodes = topology.get_nodes()  # 221ノード
    total_distance = 0
    total_hops = 0
    pair_count = 0

    for i in range(len(nodes)):
        # ノードiを起点としてダイクストラ法を実行
        distances, predecessors = dijkstra(topology, nodes[i])

        for j in range(i + 1, len(nodes)):
            # ノードiからノードjへの最短経路
            path_distance = distances[nodes[j]]
            path_hops = count_hops(predecessors, nodes[i], nodes[j])

            total_distance += path_distance
            total_hops += path_hops
            pair_count += 1

    avg_distance = total_distance / pair_count  # = 6,978.4 m
    avg_hops = total_hops / pair_count          # = 7.89 hops

    return avg_distance, avg_hops
```

**検証:**
```
平均経路距離 / 平均リンク距離 = 6,978.4 / 974.5 = 7.16
平均ホップ数 = 7.89

→ 経路はほぼ直線に近い効率的なルートが選択されている
  （7.89ホップ × 974.5m/hop = 7,687.9m vs 実測6,978.4m）
```

## 3. 理論計算（全導出過程）

### 3.1 使用する理論

**リトルの法則 (Little's Law, 1961)**

```
L = λ × W
```

| 記号 | 意味 | 単位 |
|------|------|------|
| L | システム内平均顧客数（UAV数） | 機 |
| λ | 到着率 | 機/秒 |
| W | 平均滞在時間（飛行時間） | 秒 |

### 3.2 リンク負荷率の定義（コード準拠）

**重要**: コード上の平均負荷率は**各リンクの負荷率の単純平均**として定義されている。

```java
// Link.java
loadRate = (flyingUAV + waitingUAV) / initCapacity × 100

// LinkStatusRecorder.java
平均負荷率 = Σ(各リンクの負荷率) / リンク数
```

## 4. Step-by-Step 計算

### Step 1: 平均飛行時間 W の計算

```
W = 平均経路距離 / 平均速度
```

**代入:**
```
W = 6,978.4 m / 12 m/s
  = 581.5333... 秒
  ≒ 581.53 秒
  = 9.69 分
```

**結果: W = 581.53 秒（約9.7分）**

---

### Step 2: 単純平均負荷率の理論式導出

UAVがネットワーク内に均等に分布すると仮定。

**1リンクあたりの平均UAV数:**
```
1リンクあたりUAV数 = L / 600
```

**各リンクタイプの負荷率:**
```
容量4リンク（443本）の負荷率:
  ρ_4 = (L/600) / 4 × 100
      = L × 100 / 2400
      = L / 24

容量8リンク（157本）の負荷率:
  ρ_8 = (L/600) / 8 × 100
      = L × 100 / 4800
      = L / 48
```

**単純平均負荷率 ρ_avg:**
```
ρ_avg = [443 × ρ_4 + 157 × ρ_8] / 600

      = [443 × (L/24) + 157 × (L/48)] / 600

      = [443L/24 + 157L/48] / 600

      = L × [443/24 + 157/48] / 600

      = L × [18.4583... + 3.2708...] / 600

      = L × 21.7291... / 600

      = L × 0.036215...

      ≒ L × 0.03622
```

**単純平均負荷率の公式:**
```
ρ_avg = L × 0.03622
```

---

### Step 3: 目標負荷率40%から必要UAV数 L を逆算

```
ρ_avg = 40 (%)

40 = L × 0.03622

L = 40 / 0.03622
  = 1104.36...
  ≒ 1,105 機
```

**結果: L = 1,105 機**

---

### Step 4: 必要な到着率 λ の計算

リトルの法則より:
```
L = λ × W

λ = L / W
  = 1,105 / 581.53
  = 1.9003...
  ≒ 1.90 機/秒
```

**結果: λ = 1.90 機/秒**

---

### Step 5: 平均発生間隔 T の計算

1回の生成で n=10 機のUAVを発射するため:

```
到着率 λ = n / T

T = n / λ
  = 10 / 1.90
  = 5.263...
  ≒ 5.3 秒
```

**結果: T = 5.3 秒**

## 5. 定常状態到達時間の推定

### 5.1 使用モデル

**M/G/∞待ち行列モデル**

システム内顧客数N(t)の期待値:
```
E[N(t)] = L × (1 - e^(-t/W))
```

- L: 定常状態のUAV数 = 1,105機
- W: 平均飛行時間 = 581.53秒（時定数τ）

### 5.2 到達時間の計算

**x%到達時間の公式:**
```
t = -W × ln(1 - x/100)
```

| 到達レベル | 計算式 | 計算結果 | 時間 |
|-----------|--------|----------|------|
| 63%（1τ） | t = W | 581.53秒 | 9.7分 |
| 90% | t = -581.53 × ln(0.1) | 1339.1秒 | 22.3分 |
| **95%** | t = -581.53 × ln(0.05) | **1742.3秒** | **29.0分** |
| 99% | t = -581.53 × ln(0.01) | 2676.9秒 | 44.6分 |

### 5.3 推奨ウォームアップ時間

**30分**（定常状態の95%以上に到達）

## 10. 注意事項

1. **均等分布仮定**: 理論計算ではUAVがリンクに均等分布すると仮定しているが、実際の経路探索アルゴリズム（EPS/PG-EPS/Dijkstra）では負荷の偏りが発生する

2. **待機時間の影響**: 混雑発生時は待機時間が加算され、実際の滞在時間Wが増加する。これにより定常状態のUAV数Lも増加する

3. **負荷率計算の定義**: コード上の平均負荷率は「各リンクの負荷率の単純平均」であり、「使用中容量/総容量」ではない

4. **Phase 8-Fix**: 経路計算時の容量予約機能により、ボトルネックリンクへの過剰割り当てが防止される
