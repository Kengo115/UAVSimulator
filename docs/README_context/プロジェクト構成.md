# UAVSimulator プロジェクト構成

最終更新: 2026-08-03

---

## 概要

本プロジェクトは，UAV管制（経路探索・割り当て）を担う **Operator** と，UAV飛行処理を担う **NetworkManager** を疎結合に分離したアーキテクチャのシミュレータである．両者はRedisキューを介したメッセージパッシングで協調し，直接依存を持たない．

### 3パッケージ構成の設計意図

| パッケージ | 役割 |
|---|---|
| `operator` | UAV管制（経路探索・クライアント割り当て） |
| `network_manager` | UAV飛行シミュレーション（飛行物理・リンク容量管理） |
| `shared` | 共通データ構造・Redisインフラ |

**疎結合化の利点:**
- 経路探索（Operator）と飛行シミュレーション（NetworkManager）が独立したスレッドで動作するため，あるUAVが飛行中でも次のクライアントの経路探索を並行して実行できる
- Operatorのアルゴリズム（Dijkstra / PS / EPS / PG-EPS）を変更・追加しても，NetworkManager側はUAVJobを受け取って飛ばすだけなので影響を受けない
- 経路最適化の改善は Operator 内で完結，飛行物理モデルの精緻化は NetworkManager 内で完結し，両者の変更が互いに波及しない
- OperatorとNetworkManagerがRedis経由でのみ通信しているため，将来的に別プロセス・別ホストへの分離が構造上自然に行える

## 経路探索手法一覧

シミュレーション実行時に選択する `METHOD` の一覧:

| METHOD | クラス名 | 説明 |
|---|---|---|
| `Dijkstra` | DijkstraRouteSearcher | Dijkstra最短経路 |
| `PS` | PhysarumSolverRouteSearcher | Physarum Solver |
| `EPS` | ExtendedPhysarumSolverRouteSearcher | Extended PS |
| `Bisectional` | BisectionalPressureGuidedEPSRouteSearcher | PG-EPS（二分探索）**デフォルト** |
| `PGEPS` | StepControlledPressureGuidedEPSRouteSearcher | PG-EPS（ステップ制御） |

## 結果ファイル構造

シミュレーション実行後，`src/result/sim_N/large_scale/[METHOD]/` 以下に以下のファイルが生成される:

```
[METHOD]/
├── client/
│   └── client.txt                  # 全クライアントの基本情報
├── time/
│   └── client{N}/
│       └── flight_times.csv        # UAVの各時間計測値
│                                   #   (flightTime, realFlightTime,
│                                   #    pathWaitTime, flightStayingTime,
│                                   #    waitingTime, distance 等)
├── link_status/
│   ├── link_status.csv             # 全リンクの状態（全時刻）
│   ├── congestion_rate.csv         # 時刻別混雑率
│   └── links/                      # ※extract-links実行後に生成
│       ├── link_{from}_{to}.csv    # リンク別データ
│       └── _summary.csv            # 全リンク最大負荷率集計
├── route/
│   └── client{N}/
│       └── route.csv               # 割り当て経路情報
├── snapshot/
│   └── snapshot_{timestamp}.csv    # 時刻別ネットワークスナップショット
└── capacity_exceeded.csv           # ※analyze-exceeded実行後に生成
                                    #   容量超過率分析結果
```
