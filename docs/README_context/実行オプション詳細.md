# make run 実行オプション詳細

最終更新: 2026-08-03

---

`make run` を実行すると `operator.BoundaryController` が起動し，以下の順番で対話的な設定入力を求められる．

---

## 1. ネットワーク規模の選択

```
ネットワーク規模を選択してください:
1: 小規模（詳細表示: ノードラベル・容量表示あり）
2: 大規模（シンプル表示: 地区タイプで色分け）
```

| 入力 | 効果 |
|---|---|
| `1`（デフォルト）| デフォルトトポロジを使用 |
| `2` | `config/topology/koriyama_topology.txt` を使用 |

---

## 2. トポロジファイルパスの入力

```
トポロジファイルのパスを入力してください（空欄でデフォルト: [DEFAULT_PATH]）:
>
```

- 空欄のままEnterを押すと，1で選択した規模に応じたデフォルトパスが使用される
- 別のトポロジを使用したい場合はファイルパスを入力する

---

## 3. トポロジのPNG出力

```
トポロジをPNG画像として出力しますか？
1: 出力しない
2: 出力する (output/ディレクトリに保存)
```

| 入力 | 効果 |
|---|---|
| `1`（デフォルト）| スキップ |
| `2` | Pythonスクリプトで `output/` にPNG画像を生成 |

---

## 4. 経路探索手法の選択

```
経路探索手法を選択してください:
1: Dijkstra法
2: PhysarumSolver法 (PS)
3: ExtendedPhysarumSolver法 (EPS)
4: ハイブリッド法 (HYBRID: EPS+PS)
5: バイナリサーチ法 (BINARY: Binary Search EPS+PS)
6: 二分法型圧力誘導法 (BISECTIONAL_PG-EPS)
7: ステップ制御型圧力誘導法 (STEP_CONTROLLED_PG-EPS)
```

| 入力 | 手法名 | 結果ディレクトリ名 | 説明 |
|---|---|---|---|
| `1` | Dijkstra | `Dijkstra` | Dijkstra最短経路 |
| `2` | PS | `PS` | Physarum Solver（生物模倣型） |
| `3`（デフォルト）| EPS | `EPS` | Extended Physarum Solver |
| `4` | HYBRID | `Hybrid` | EPS + PS ハイブリッド |
| `5` | BINARY | `Binary` | バイナリサーチ型 EPS+PS |
| `6` | BISECTIONAL_PG-EPS | `Bisectional` | 二分探索型 PG-EPS |
| `7` | STEP_CONTROLLED_PG-EPS | `PGEPS` | ステップ制御型 PG-EPS |

> **注意:** 結果ファイルは `src/result/sim_N/large_scale/[結果ディレクトリ名]/` に保存される．分析コマンドの `METHOD=` にはこの名前を指定する．

---

## 5. ログ記録の設定

```
ログをファイルに記録しますか？
1: 記録しない
2: 記録する (log/simulator.logに記録)
```

| 入力 | 効果 |
|---|---|
| `1`（デフォルト）| ログ記録なし |
| `2` | `src/log/sim_N/simulator.log` に記録 |

`2` を選択すると以下のメッセージが表示され，別ターミナルでリアルタイム確認が可能:
```
ログは log/simulator.log に記録されます。
別のターミナルで 'tail -f log/simulator.log' を実行すると、リアルタイムでログを確認できます。
```

---

## 6. シミュレーション設定ファイルの読み込み

```
シミュレーション設定ファイルを読み込みますか？
1: 読み込まない（デフォルト設定を使用）
2: 読み込む（config/simulation_params.json）
3: ファイルパスを指定して読み込む
```

| 入力 | 効果 |
|---|---|
| `1`（デフォルト）| デフォルト設定を使用 |
| `2` | `config/simulation_params.json` を読み込む |
| `3` | 後続のプロンプトでパスを指定 |

`3` を選択した場合，追加入力を求められる:
```
設定ファイルのパスを入力してください:
```

---

## 7. クライアント生成モードの選択

```
クライアント生成モードを選択してください:
1: スケジュールファイルから読み込み
2: ランダム生成（固定数）
3: 4フェーズ制御（動的生成）
4: 統計的シミュレーション（指数分布）
```

各モードの詳細は以下の通り:

---

### モード 1: スケジュールファイルから読み込み

```
スケジュールファイルのパスを入力してください（空欄でデフォルト: [DEFAULT_SCHEDULE_PATH]）:
```

- 空欄で `config/schedule/client_schedule.csv` を使用
- CSVファイルに定義されたクライアントを順番に処理する

---

### モード 2: ランダム生成（固定数）

シード値とクライアント数を指定してランダムにクライアントを生成する:

```
シード値を入力してください（空欄でデフォルト: 12345）:

生成するクライアント数を入力してください（空欄でデフォルト: 10）:
```

| パラメータ | デフォルト | 説明 |
|---|---|---|
| シード値 | `12345` | 乱数シード（再現性に影響） |
| クライアント数 | `10` | 生成するUAVクライアントの総数 |

---

### モード 3: 4フェーズ制御

追加入力なし．設定ファイルの `simulation_params.json` に従い，以下の4フェーズを順番に実行する:

| フェーズ | 内容 |
|---|---|
| Phase 1（生成期）| 混雑率が閾値以上になるまでUAVを連続生成 |
| Phase 2（安定期）| 目標混雑率付近を維持しながら一定時間動作 |
| Phase 3（混雑期）| 高頻度でUAVを生成し意図的に混雑させる |
| Phase 4（回復期）| UAV生成を止め，シミュレーション終了まで回復を観察 |

---

### モード 4: 統計的シミュレーション（大規模実験）

追加入力なし．`config/statistical_params.json` の設定に従い，指数分布に基づくUAV到着モデルで長時間シミュレーションを実行する．研究用の主要シミュレーションモード．

起動時に以下の情報が表示される:
```
=== 統計的シミュレーションモード ===
シミュレーション時間: [HOURS]時間
平均発生間隔: [INTERVAL]秒（指数分布）
1回あたりUAV数: [UAV_COUNT]機
✓ 統計的シミュレーションを開始しました (seed=[SEED])
```

設定の変更は `config/statistical_params.json` を編集する（詳細は [実行方法.md](./実行方法.md) 参照）．

---

## 典型的な実行パターン

**研究用大規模シミュレーション（PG-EPS）:**

```
1 → ネットワーク規模: 2（大規模）
2 → トポロジ: 空欄（デフォルト）
3 → PNG出力: 1（しない）
4 → 経路探索: 6（BISECTIONAL_PG-EPS）
5 → ログ: 1（しない）
6 → 設定ファイル: 2（statistical_params.json）
7 → 生成モード: 4（統計的シミュレーション）
```

**小規模テスト（Dijkstra・少数クライアント）:**

```
1 → ネットワーク規模: 1（小規模）
2 → トポロジ: 空欄（デフォルト）
3 → PNG出力: 1（しない）
4 → 経路探索: 1（Dijkstra）
5 → ログ: 2（記録する）
6 → 設定ファイル: 1（読み込まない）
7 → 生成モード: 2（ランダム生成）
   シード値: 空欄（12345）
   クライアント数: 5
```
