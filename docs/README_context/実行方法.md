# UAVSimulator 実行方法

最終更新: 2026-08-03

---

## 前提条件

- Java (Maven)
- Docker（Redis用）
- Python 3（分析ツール用）

---

## 基本的な実行手順

### 1. シミュレータを起動する

```bash
make run SIM_ID=N
```

`make run` は以下を自動で実行する:
1. Mavenコンパイル（`mvn compile`）
2. Redis未起動の場合は自動起動（Docker）
3. 同じ SIM_ID の古いプロセスを停止
4. シミュレーション開始（`operator.BoundaryController`）

コンパイル済みの場合は `make run-quick` でコンパイルをスキップできる:

```bash
make run-quick SIM_ID=N
```

短時間テストなどでJVMメモリ制限を外す場合:

```bash
make run-light SIM_ID=N
```

`SIM_ID` を省略した場合は `SIM_ID=1` として実行される.

## 並列シミュレーション

複数のターミナルで同時に異なる SIM_ID を指定することで，並列実行が可能.

```
ターミナル1: make run SIM_ID=1
ターミナル2: make run SIM_ID=2
ターミナル3: make run SIM_ID=3
```

| SIM_ID | Redisポート | 結果出力先 | ログ出力先 |
|---|---|---|---|
| 1 | 6379 | src/result/sim_1/ | src/log/sim_1/ |
| 2 | 6380 | src/result/sim_2/ | src/log/sim_2/ |
| N | 6378+N | src/result/sim_N/ | src/log/sim_N/ |

## Redis管理コマンド

| コマンド | 説明 |
|---|---|
| `make up` | SIM_ID=1用 Redisコンテナを手動起動 |
| `make down` | SIM_ID=1用 Redisコンテナを停止 |
| `make down-all` | 全シミュレータと全 Redisコンテナを停止 |
| `make restart` | Redisコンテナを再起動 |
| `make status` | 起動中のコンテナ一覧を表示 |
| `make logs` | Redisコンテナのログを表示 |
| `make redis-clear` | SIM_ID=1用 Redisのデータをクリア |
| `make stop-all` | 全シミュレーションプロセスを停止 |

## 設定ファイル

### `config/statistical_params.json`（統計的シミュレーション）

大規模シミュレーション（指数分布到着モデル）の設定. 通常の研究シミュレーションで使用する.

```json
{
  "seed": 12345,                        // 乱数シード
  "simulation_duration_hours": 1.0,     // シミュレーション時間（時間）
  "snapshot_interval_sec": 10,          // スナップショット取得間隔（秒）

  "arrival": {
    "mean_interval_sec": 6.67,          // UAV到着の平均間隔（秒）
    "uav_count_per_batch": 10,          // 1バッチあたりのUAV数
    "distribution": "exponential"       // 到着分布（指数分布）
  },

  "steady_state": {
    "target_load_percent": 40.0,        // 定常状態の目標負荷率（%）
    "tolerance_percent": 5.0,           // 許容誤差（%）
    "observation_window_minutes": 5     // 観測ウィンドウ（分）
  },

  "warmup": {
    "duration_minutes": 30,             // ウォームアップ期間（分）
    "discard_data": true                // ウォームアップ中データを破棄するか
  },

  "congestion_event": {
    "enabled": false,                   // 混雑イベントの有効化
    "interval_minutes": 30,             // イベント発生間隔
    "duration_minutes": 10,             // イベント継続時間
    "target_load_percent": 80.0         // イベント中の目標負荷率
  }
}
```

**変更時の影響:**
- `mean_interval_sec` を小さくすると到着頻度が増加しネットワーク負荷が上昇する
- `warmup.discard_data: true` の間の結果は集計対象外になる
- `seed` を変えると再現性が失われる（意図的に変更する場合を除く）

### `config/simulation_params.json`（フェーズ制御シミュレーション）

フェーズ1〜4（生成・安定・混雑・回復）を順に遷移させる小規模シミュレーション設定.

```json
{
  "seed": 12345,
  "duration_minutes": 90,              // 全体の実行時間（分）
  "snapshot_interval_sec": 10,
  "topology": null,                    // nullの場合はデフォルトトポロジを使用
  "route_search_method": null,         // nullの場合は実行時に選択
  "phases": {
    "phase1_generation": { ... },      // フェーズ1: UAV生成フェーズ
    "phase2_stable": { ... },          // フェーズ2: 安定フェーズ
    "phase3_congestion": { ... },      // フェーズ3: 混雑フェーズ
    "phase4_recovery": { ... }         // フェーズ4: 回復フェーズ
  }
}
```

---

### `config/topology/koriyama_topology.txt`

郡山市ドローン空路トポロジ（主要シミュレーションで使用）. テキスト形式でノードとリンクを定義する.

---

### `config/schedule/client_schedule.csv`

スケジュール実行モードで使用するクライアント定義ファイル. 各クライアントの出発ノード・目的ノード・発生時刻等を記述する.

---

## 結果ファイルの格納場所

シミュレーション実行後，以下のディレクトリに結果が出力される:

```
src/result/sim_N/large_scale/[METHOD]/
  ├── client/           クライアント情報（client.txt）
  ├── time/             UAV別飛行時間記録（flight_times.csv）
  ├── link_status/      リンク状態・混雑率 CSV
  ├── route/            クライアント別割り当て経路
  └── snapshot/         時刻別ネットワークスナップショット CSV
```

`[METHOD]` はシミュレーション実行時に選択した経路探索手法名（`Bisectional`, `PS`, `EPS`, `PGEPS`, `Dijkstra` のいずれか）に対応する.
