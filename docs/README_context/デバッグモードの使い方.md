# デバッグモードの使い方

最終更新: 2026-08-04

---

## 概要

デバッグモードは、ブラウザUIからUAVの経路探索・飛行をインタラクティブに操作・可視化するモードである。通常のシミュレーションとは異なり、クライアント（出発地・目的地・UAV台数）を手動で指定し、経路確定後に飛行開始ボタンを押すことでフライトが始まる。

---

## 起動方法

```bash
# コンパイルあり
make run-debug

# コンパイル済みの場合（高速起動）
make run-debug-quick
```

起動後、ブラウザで以下のURLを開く:

```
http://localhost:9001
```

**内部動作:**
- `make run-debug` は Java プロセス（`BoundaryController`）と Python プロセス（`debug_server.py`）を起動する
- Java プロセスは環境変数 `DEBUG_MODE=true` で起動し、`DebugModeController` がRedis pub/sub を通じてUIと通信する
- Python プロセスはWebサーバー（ポート9001）として動作し、WebSocket でフロントエンドとリアルタイム通信する

---

## UI の操作手順

### 1. クライアントを作成する

1. 「**出発ノード選択**」ボタンを押してトポロジ上のノードをクリック（緑でハイライト）
2. 「**到着ノード選択**」ボタンを押してトポロジ上の別ノードをクリック（赤でハイライト）
3. UAV台数・経路探索手法を選択
4. 「**経路割り当て**」ボタンを押す → Java側で経路探索が実行される

**経路探索手法の選択肢:**

| 番号 | 手法名 | 説明 |
|---|---|---|
| 1 | Dijkstra | 最短経路（ホップ数最小） |
| 2 | PS (PhysarumSolver) | 生物模倣型ネットワーク最適化 |
| 3 | EPS (ExtendedPS) | 容量制約付き PS |
| 4 | Hybrid (EPS+PS) | EPS + PS ハイブリッド |
| 5 | Binary Search EPS+PS | バイナリサーチ型 |
| 6 | Bisectional PG-EPS | 二分探索型 PG-EPS（推奨） |
| 7 | StepControlled PG-EPS | ステップ制御型 PG-EPS |

---

### 2. 経路を確認する

経路探索完了後、**飛行開始待ち**タブに該当クライアントが表示される。

- クライアント情報（`src → dst (N台)`）が表示される
- 各UAV番号のボタンが並ぶ

**UAV別経路表示:**
- UAV番号ボタンを押す → そのUAVのS-D経路のみトポロジ上に橙色の矢印で表示される
- 同じボタンを再押し → 全UAVの経路表示に戻る

---

### 3. 飛行を開始する

「**飛行開始**」ボタンを押すと:
- 経路矢印が消える
- UAVが飛行開始（トポロジ上に円として表示される）
- 飛行開始待ちリストからそのクライアントが削除される

複数クライアントを同時に飛行させることも可能。

---

### 4. 一時停止 / 再開

| ボタン | 動作 |
|---|---|
| **一時停止** | 全UAVの飛行をその場で停止。経過時間も停止。 |
| **再開** | 一時停止状態から飛行を再開。 |

---

### 5. 初期化（リセット）

「**初期化**」ボタンを押すと確認ダイアログが表示され、承認すると:

1. 飛行中の全UAVジョブをキャンセル（`FlightScheduler.cancelAllFlights()`）
2. Redis の全データを削除（`flushdb`）
3. UAVワーカーを再起動
4. UIの状態（UAV表示・経路・クライアント一覧）をリセット

> **注意:** リセット後は経路探索から再度やり直しとなる。飛行中のUAVが即時消える。

## 表示の見方

### トポロジ表示

| 表示 | 意味 |
|---|---|
| 小さい円（濃青） | ネットワークノード |
| 橙色の矢印 | 飛行開始前の確定経路 |
| 赤い円 | 飛行中のUAV（`FLYING`） |
| 青い円 | ホバリング中のUAV（`HOVERING`、容量超過待ち） |
| 緑の円 | 飛行前待機中のUAV（`PRE_WAIT`） |

### UAVカウント

画面上部に表示される「UAV数」は**現在アクティブなUAVのみ**をカウントする（飛行完了したUAVはカウント外）。

- 飛行完了したUAVは Redis から削除されるため、次回のWebSocket更新（200ms間隔）以降は表示されなくなる

## 通信アーキテクチャ

```
ブラウザ (Vue 3 UI)
    ↕ WebSocket (port 9001)
Python debug_server.py
    ↕ Redis pub/sub (debug:command チャンネル)
Java DebugModeController / DebugModeHook
    ↕ Redis (UAVJobQueue, LinkCapacityManager, VizStateManager)
Java FlightScheduler / AsyncUAVWorker
```

**Redis チャンネルメッセージ形式:**

| 方向 | メッセージ | 意味 |
|---|---|---|
| Python → Java | `ASSIGN:{src}:{dst}:{uavCount}:{method}` | 経路探索依頼 |
| Python → Java | `FLY:{clientId}` | 飛行開始承認 |
| Python → Java | `PAUSE` | 一時停止 |
| Python → Java | `RESUME` | 再開 |
| Python → Java | `RESET` | 初期化 |
| Java → Python | `ROUTES_READY:{clientId}` | 経路探索完了通知 |
| Java → Python | `RESET_DONE` | 初期化完了通知 |

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| UIが真っ白 / 接続中のまま | debug_server.py が起動していない。`make run-debug` をやり直す |
| 経路割り当てボタンを押しても反応しない | Java側のログを確認。Redisに接続できていない可能性あり |
| リセット後にUAVが残る | 正常動作。WebSocketの次回ポーリング（最大200ms）で消える |
| グリーディ探索になる | 収束イテレーションが不足。BisectionalPGEPSのパラメータを参照 |
