1. 研究背景と目的
================================================================================

【背景】
UAV（無人航空機）ネットワークにおける最適経路探索問題に対し、生物学的アルゴ
リズム（Physarum Solver：粘菌アルゴリズム）を応用した研究を実施中。

【従来手法の課題】
- PhysarumSolver (PS): 容量制約を考慮できない
- ExtendedPhysarumSolver (EPS): 容量制約を考慮するが、過負荷時に計算が破綻
- HybridPhysarumSolver (初期版): EPS段階的増加方式は複雑で非効率

【研究目的】
EPSが要求フローに対して、ネットワークの最大フロー容量まで「ぴったり」適応
できる適応的フロー制御アルゴリズムの開発。

2. 現在の実装状況（本日開始時点）
================================================================================

【実装済み機能】
✓ P_tubePressure（圧力値）出力機能の追加
  - ResultOutputManager.outputToTxt()にP_tubePressure配列パラメータ追加
  - CSVヘッダーにsourcePressure, destPressureカラム追加
  - 各リンクのソース・デスティネーション圧力値を出力

✓ 予防型不安定性検知システム
  - 3つの指標: 圧力勾配、圧力絶対値、チューブ厚変化率
  - 統合スコア方式による早期警告・緊急対応

✓ 適応的フロー減少機構
  - 要求フロー値から開始
  - 不安定性検知時に2UAVまたは1UAV減少
  - 最小安全フロー: 要求フローの80%
  - 振動防止: 最大5回までの減少制限

【課題】
✗ フロー減少のみで、増加機構が存在しない
  → 最大フローまで到達できず、過小に収束してしまう

例: 最大フロー30、要求フロー32の場合
  現状: 32 → 30 → 28 → 収束(28) ❌ 過小収束
  理想: 32 → 30 → 28 → 29 → 30 → 収束(30) ✅ 最適

3. 実データ分析結果
================================================================================

【分析対象】
要求フロー31 vs ネットワーク最大フロー30の過負荷ケース

【破綻パターンの発見】

イテレーション | ソース圧力 | 最大圧力差 | 負チューブ厚 | 状態
--------------|-----------|-----------|-------------|----------
15回目        | 88.56     | 119.18    | なし        | 軽微不安定
22回目        | 158.01    | 226.01    | なし        | 中程度不安定

【重要な知見】
1. 圧力値の急激な増大が破綻の前兆（25→26回目で10倍増）
2. 負のチューブ厚出現が致命的レベルの指標
3. 圧力絶対値監視の重要性を確認（従来は圧力勾配のみ）

【閾値の決定根拠】
上記実データ分析より、以下の閾値を設定：
- 圧力勾配警告: 100.0、緊急: 200.0
- 圧力絶対値警告: 150.0、緊急: 300.0（⭐新指標）
- チューブ厚変化率警告: 0.05、緊急: 0.10

4. 本日の議論内容：双方向適応的フロー制御
================================================================================

【問題提起】
現在の実装は「片方向（減少のみ）」の適応制御であり、最大フローを探索できない。

例: 最大フロー30、要求フロー32
  現状: 32 → 不安定検知 → 30 → 不安定検知 → 28 → 安定 → 収束(28)
  問題点: 28で収束してしまい、最大フロー30に到達できない

【解決方針】
双方向適応制御の導入
- フロー減少: 不安定性検知時（既存機能）
- フロー増加: 安定時に最大フローを探索（新機能）⭐

【検討した実装アプローチ】

(1) 線形探索方式
  - 方法: 安定後、1UAVずつ慎重に増加
  - 安全性: ⭐⭐⭐⭐⭐
  - 効率: ⭐⭐
  - 適用場面: 小さなギャップ（残り1-3UAV）の探索

(2) 適応的増加量方式
  - 方法: 不安定性スコアに応じて増加量を動的調整
  - 安全性: ⭐⭐⭐⭐
  - 効率: ⭐⭐⭐⭐
  - 適用場面: 中程度のギャップ（残り5-10UAV）の探索

(3) 二分探索方式
  - 方法: 安定範囲と不安定範囲の境界を二分探索
  - 安全性: ⭐⭐⭐
  - 効率: ⭐⭐⭐⭐⭐
  - 適用場面: 大きなギャップ（残り10UAV以上）の探索

(4) ハイブリッド方式（推奨）⭐⭐⭐⭐⭐
  - 方法: ギャップサイズに応じて(2)と(1)を使い分け
  - 大きなギャップ: 適応的に大きく増加（5UAV, 3UAV, 2UAV）
  - 小さなギャップ: 慎重に線形探索（1UAVずつ）
  - 安全性: ⭐⭐⭐⭐
  - 効率: ⭐⭐⭐⭐⭐
  - 総合評価: 最もバランスが良い

5. 提案アルゴリズム（ハイブリッド方式）
================================================================================

【基本フロー】
1. currentFlow = requestedFlow で開始
2. EPS計算を1イテレーション実行
3. 予防型不安定性スコアを計算
4. 判定:
   - スコア >= 5.0 (緊急): 2UAV減少 → ステップ2へ
   - スコア >= 3.0 (警告): 1UAV減少 → ステップ2へ
   - スコア < 3.0 (安定): 安定カウンター++ → ステップ5へ
5. 安定カウンターが50に到達した場合:
   - 残りギャップ > 5UAV: 適応的増加（2-5UAV）→ ステップ2へ
   - 残りギャップ <= 5UAV: 線形増加（1UAV）→ ステップ2へ
   - 残りギャップ = 0 または currentFlow = requestedFlow: 継続安定確認
6. 安定カウンターが500に到達: 収束完了

【増加量決定ロジック】
```
if (残りギャップ > 5UAV) {
    if (スコア < 0.5) → 5UAV増加 または 残りギャップの50%
    if (スコア < 1.5) → 3UAV増加 または 残りギャップの30%
    if (スコア >= 1.5) → 2UAV増加
}
else if (残りギャップ <= 5UAV) {
    if (スコア < 1.0) → 1UAV増加（慎重）
    if (スコア >= 1.0) → 増加しない（安定優先）
}
```

【振動防止機構】
- フロー減少回数上限: 5回
- フロー増加回数上限: 5回
- 各フロー変更後、安定カウンターをリセット
- 50回連続安定で次の増加を試行

【動作例】
最大フロー30、要求フロー32の場合

イテレーション | フロー | スコア | 判定 | アクション | 安定カウント
--------------|-------|--------|------|-----------|-------------
1-10          | 32    | 6.5    | 緊急 | -2UAV     | 0
11-20         | 30    | 4.2    | 警告 | -1UAV     | 0
21-70         | 29    | 0.8    | 安定 | なし      | 0→50
71            | 29    | 0.8    | 安定 | +1UAV⭐   | 50→0
72-121        | 30    | 1.8    | 安定 | なし      | 0→50
122           | 30    | 1.8    | 安定 | +1UAV試行 | 50→0
123-130       | 31    | 4.5    | 警告 | -1UAV     | 0
131-630       | 30    | 1.8    | 安定 | なし      | 0→500
収束          | 30    | -      | -    | 完了✅    | -

結果: 最大フロー30で収束（理想的！）

6. 期待される効果
================================================================================

【定量的効果】
1. 最大フロー到達率の向上
   従来: 約80-90%（過小収束）
   改善後: 約98-100%（最適収束）⭐

2. イテレーション数の最適化
   線形探索のみの場合: 大きなギャップで非効率
   ハイブリッド方式: O(log n)に近い効率を実現

3. 収束安定性の向上
   慎重な境界探索により、安定した収束を保証

【定性的効果】
1. ネットワーク容量の最大活用
   → UAVリソースの効率的利用

2. 過負荷時の自動調整
   → システムの自己適応性向上

3. 計算の安定性向上
   → 予防的検知による破綻回避
