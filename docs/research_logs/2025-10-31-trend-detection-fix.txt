1. 問題の発見
================================================================================

【実行ログからの観察】
最大フロー30のネットワークに対して、フロー31で364回のイテレーション（269-632）が
「安定」と誤判定される問題が発見された。

イテレーション | フロー | スコア | 判定
--------------|-------|--------|------
269           | 31    | 0.369  | 安定
340           | 31    | 1.073  | 安定
400           | 31    | 1.679  | 安定
500           | 31    | 2.277  | 安定
632           | 31    | 2.981  | 安定
633           | 31    | 3.16   | 早期警告（ようやく検知）
640           | 31    | 5.03   | 緊急対応

【問題点】
スコアが0.369から2.981まで徐々に上昇（約364イテレーションで約2.6増加）
→ 平均増加率: 約0.0072/iteration

この上昇トレンドは明らかに不安定化の前兆であるが、従来の判定ロジックは
「スコア < 3.0」という絶対的閾値のみをチェックしていたため、検知できなかった。

【根本原因】
従来の安定性判定（行202-242）：
```java
if (instabilityScore < EARLY_WARNING_THRESHOLD) { // < 3.0
    // 安定と判定
    stableIterationCount++;
}
```
→ トレンド（変化率）を考慮していない

2. 実装した解決策
================================================================================

【アプローチ】
トレンドベースの不安定性検知を追加
- スコアの履歴を記録
- 最小二乗法による線形回帰で傾き（増加率）を計算
- 増加率が閾値を超えた場合、トレンドベース不安定性として検知

【追加した定数】
1. SCORE_HISTORY_SIZE = 20
   スコア履歴のサイズ（過去20イテレーション分を記録）

2. MAX_ACCEPTABLE_SCORE_INCREASE_RATE = 0.015
   許容最大スコア増加率（イテレーションあたり）
   → 0.015/iter = 約300イテレーションで閾値3.0到達（20 * 0.015 * 10 = 3.0）

3. TREND_WARNING_THRESHOLD = 0.010
   トレンド早期警告閾値
   → 0.010/iter = 約500イテレーションで閾値3.0到達

【追加した変数】
1. instabilityScoreHistory: double[]
   スコア履歴配列（サーキュラーバッファ）

2. scoreHistoryIndex: int
   履歴配列のインデックス

3. scoreHistoryCount: int
   記録済みスコア数


【追加したメソッド】

1. recordScoreInHistory(double score): void
   - スコアを履歴に記録
   - サーキュラーバッファで実装（古いデータは上書き）

2. calculateScoreIncreaseRate(): double
   - 最小二乗法による線形回帰で傾き（増加率）を計算
   - 履歴が5未満の場合は0.0を返す
   - 返り値: スコアの増加率（イテレーションあたり）

3. detectTrendBasedInstability(double currentScore, double scoreIncreaseRate): boolean
   - トレンドに基づく不安定性を検知
   - 条件1: 増加率 > MAX_ACCEPTABLE_SCORE_INCREASE_RATE (0.015)
     → 緊急レベルのトレンド不安定性
   - 条件2: 増加率 > TREND_WARNING_THRESHOLD (0.010) かつ スコア > 閾値の70% (2.1)
     → 早期警告レベルのトレンド不安定性
   - 返り値: トレンド不安定性が検知された場合true


【メインループの修正】

修正前（行214-242）:
```java
// 予防型不安定性検知
double instabilityScore = calculatePreventiveInstabilityScore();

if (instabilityScore >= EMERGENCY_THRESHOLD) {
    // 緊急対応
} else if (instabilityScore >= EARLY_WARNING_THRESHOLD) {
    // 早期警告
} else {
    // 安定状態
}
```

修正後（行214-277）:
```java
// 予防型不安定性検知
double instabilityScore = calculatePreventiveInstabilityScore();

// スコアを履歴に記録（⭐誤陽性防止⭐）
recordScoreInHistory(instabilityScore);

// トレンドを計算（⭐誤陽性防止⭐）
double scoreIncreaseRate = calculateScoreIncreaseRate();

// トレンドベースの不安定性検知（⭐誤陽性防止⭐）
boolean trendBasedInstability = detectTrendBasedInstability(instabilityScore, scoreIncreaseRate);

if (instabilityScore >= EMERGENCY_THRESHOLD) {
    // 緊急対応
} else if (instabilityScore >= EARLY_WARNING_THRESHOLD) {
    // 早期警告
} else if (trendBasedInstability) {
    // ⭐トレンドベース不安定性：1UAV減少（誤陽性防止）⭐
    if (applyUAVFlowReduction(WARNING_FLOW_REDUCTION_UAV, "Trend-based instability")) {
        consecutiveStableForIncrease = 0;
        ct++;
        continue;
    }
} else {
    // 安定状態
}
```

3. アルゴリズムの動作原理
================================================================================

【最小二乗法による線形回帰】
過去20イテレーションのスコア履歴から、最小二乗法で直線の傾きを求める。

傾き（slope）= (n*ΣXY - ΣX*ΣY) / (n*ΣX² - (ΣX)²)

- X: イテレーション番号（0, 1, 2, ..., 19）
- Y: 各イテレーションのスコア
- n: 履歴サイズ（20）

【トレンド検知の判定ロジック】

条件1: 緊急レベルのトレンド不安定性
- 増加率 > 0.015/iter
- ログ: "Trend-based instability detected! Score increase rate: X.XXXX per iteration"
- 対応: 1UAV減少

条件2: 早期警告レベルのトレンド不安定性
- 増加率 > 0.010/iter かつ 現在スコア > 2.1
- ログ: "Trend-based early warning! Score increase rate: X.XXXX per iteration"
- 対応: 1UAV減少

条件3: 安定（条件1, 2を満たさない場合）
- トレンド不安定性なし
- 通常の安定判定へ進む

4. 期待される効果
================================================================================

【定量的効果】

1. 誤陽性の削減
   従来: スコアが徐々に上昇している場合でも「安定」と判定
   改善後: トレンドを検知して早期にフロー減少

2. 早期検知の実現
   従来: スコアが3.0に到達してから検知（約364イテレーション後）
   改善後: トレンドが0.010/iterを超えた時点で検知（推定: 約100-150イテレーション後）

3. 計算破綻の防止
   従来: スコアが5.03に達してから緊急対応（手遅れになりやすい）
   改善後: トレンドを検知して予防的にフロー減少

【定性的効果】

1. フロー減少回数の削減
   早期にトレンドを検知することで、緊急対応（2UAV減少）ではなく
   早期警告レベル（1UAV減少）で対処可能

2. より正確な最大フロー探索
   誤陽性が減ることで、真の最大フローに到達しやすくなる

3. アルゴリズムの頑健性向上
   トレンドベース検知により、様々なネットワークトポロジーに対応可能

6. 閾値の設計根拠
================================================================================

【MAX_ACCEPTABLE_SCORE_INCREASE_RATE = 0.015】
- 実データ分析より、平均増加率 ≈ 0.0072/iter
- 安全マージンを考慮して約2倍の0.015/iterを設定
- 約200イテレーション以内でスコアが3.0に到達する場合に検知

【TREND_WARNING_THRESHOLD = 0.010】
- 早期警告レベルとして、緊急閾値の約2/3を設定
- 約300イテレーション以内でスコアが3.0に到達する場合に検知
- 現在スコアが2.1（閾値の70%）以上の場合のみ適用

【SCORE_HISTORY_SIZE = 20】
- 短期的なノイズを平滑化しつつ、トレンドを正確に捉えられるサイズ
- 20イテレーション = 約0.2秒（PLOT = 10の場合、2回分の出力）
