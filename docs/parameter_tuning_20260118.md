## 4. 理論計算

### 4.1 使用した理論

**リトルの法則 (Little's Law, 1961)**

```
L = λ × W
```

- L: システム内平均顧客数（UAV数）
- λ: 到着率
- W: 平均滞在時間（飛行時間）

### 4.2 リンク負荷率の定義（コード準拠）

**重要**: コード上の平均負荷率は**各リンクの負荷率の単純平均**として定義されている。

```java
// Link.java
loadRate = (flyingUAV + waitingUAV) / initCapacity × 100

// LinkStatusRecorder.java
平均負荷率 = Σ(各リンクの負荷率) / リンク数
```

### 4.3 計算手順

#### Step 1: 平均飛行時間（変更なし）

```
W = 平均経路距離 / 平均速度
  = 6,978.4 m / 12 m/s
  = 581.53 秒 (9.69分)
```

#### Step 2: 単純平均負荷率から必要UAV数を導出

各リンクにUAVが均等に分布すると仮定した場合：

```
1リンクあたりの平均UAV数 = L / 600

各リンクの負荷率:
- 容量4リンク（443本）: (L/600) / 4 × 100 = L × 100 / 2400
- 容量8リンク（157本）: (L/600) / 8 × 100 = L × 100 / 4800

平均負荷率 ρ_avg:
ρ_avg = [443 × (L/600)/4 + 157 × (L/600)/8] / 600 × 100
      = (L/600) × (443/4 + 157/8) / 600 × 100
      = (L/600) × (110.75 + 19.625) / 600 × 100
      = L × 130.375 / 360000 × 100
      = L × 0.03622
```

目標負荷率30%から逆算:

```
30 = L × 0.03622
L = 30 / 0.03622
L = 828.3 機 ≒ 829 機
```

#### Step 3: 必要な到着率

```
λ = L / W
  = 829 / 581.53
  = 1.426 機/秒
```

#### Step 4: 平均発生間隔

```
T = n / λ （n: 1回あたりの生成数 = 10機）
  = 10 / 1.426
  = 7.01 秒 ≒ 7.0 秒
```

## 5. 定常状態到達時間の推定

### 5.1 使用したモデル

**M/G/∞待ち行列モデル**

システム内顧客数N(t)の期待値:

```
E[N(t)] = L × (1 - e^(-t/W))
```

- L: 定常状態のUAV数 = 829機
- W: 平均飛行時間 = 581.53秒（時定数τ）

### 5.2 到達時間の計算

| 到達レベル | 計算式 | 時間 |
|-----------|--------|------|
| 63%（1τ） | t = W | 9.7分 |
| 90% | t = -W × ln(0.1) | 22.3分 |
| **95%** | t = -W × ln(0.05) | **29.0分** |
| 99% | t = -W × ln(0.01) | 44.6分 |

### 5.3 推奨ウォームアップ時間

**30分**（定常状態の95%以上に到達）

## 8. 各数値の詳細な導出過程

### 8.1 平均飛行時間（9.7分 = 581.53秒）

**導出方法**: ダイクストラ法による全点対最短経路計算（変更なし）

```
Step 1: トポロジーからグラフを構築
  - 221ノード、600リンク（無向グラフとして扱う）

Step 2: 全ノードペアの最短経路計算
  - 221×220÷2 = 24,310ペアの経路距離を計算

Step 3: 結果
  平均経路距離 = 6,978.4 m

Step 4: 平均飛行時間の計算
  UAV速度 = 8〜16 m/s（コードより: speed = 8 + random * 8）
  平均速度 = (8 + 16) / 2 = 12 m/s

  平均飛行時間 W = 平均経路距離 / 平均速度
                = 6,978.4 m / 12 m/s
                = 581.53 秒
                = 9.69 分 ≒ 9.7分
```

### 8.2 予想システム内UAV数（829機）

**導出方法**: 単純平均負荷率の定義から逆算

```
Step 1: コード上の負荷率定義を確認
  - Link.java: loadRate = (flying + waiting) / initCapacity × 100
  - LinkStatusRecorder.java: 平均負荷率 = Σ(各リンク負荷率) / リンク数

Step 2: 均等分布を仮定した理論式
  1リンクあたりの平均UAV数 = L / 600

  容量4リンク（443本）の負荷率: (L/600) / 4 × 100
  容量8リンク（157本）の負荷率: (L/600) / 8 × 100

  平均負荷率 = [443×(L/600)/4 + 157×(L/600)/8] / 600 × 100
             = L × 0.03622

Step 3: 目標負荷率から必要UAV数を計算
  目標 ρ_avg = 30%

  30 = L × 0.03622
  L = 30 / 0.03622
  L = 828.3 機 ≒ 829機
```

### 8.3 平均発生間隔（7.0秒）

**導出方法**: リトルの法則から逆算

```
Step 1: リトルの法則
  L = λ × W
  ここで:
    L = システム内平均UAV数 = 829機
    W = 平均滞在時間 = 581.53秒
    λ = 到着率（機/秒）

Step 2: 到着率を求める
  λ = L / W
    = 829 / 581.53
    = 1.426 機/秒

Step 3: 平均発生間隔を計算
  1回の生成で10機のUAVを発射するため:

  到着率 λ = UAV生成数 n / 平均発生間隔 T

  T = n / λ
    = 10 / 1.426
    = 7.01 秒 ≒ 7.0秒
```

### 8.4 定常状態到達時間（30分）

**導出方法**: M/G/∞待ち行列モデルによる過渡解析

```
Step 1: M/G/∞モデルの過渡解
  E[N(t)] = L × (1 - e^(-t/W))

Step 2: 95%到達時間を計算
  0.95 = 1 - e^(-t/W)
  e^(-t/W) = 0.05
  -t/W = ln(0.05)
  t = -W × ln(0.05)
    = -581.53 × (-2.996)
    = 1742.3 秒
    = 29.0 分 ≒ 30分
```

## 11. 注意事項

- これは理論値であり、実際のシミュレーションでは以下の要因により調整が必要になる可能性がある:
  - 経路探索アルゴリズムによる負荷の偏り（均等分布仮定からの乖離）
  - 待機時間の発生による滞在時間の増加
  - ネットワーク構造による局所的な混雑

- 定常状態の判定は「観測」によって行い、理論値からの乖離を確認する

- ウォームアップ時間30分は95%到達の目安であり、より厳密な定常状態が必要な場合は45分（99%到達）を推奨

- **負荷率計算の注意点**: コード上の平均負荷率は「各リンクの負荷率の単純平均」であり、「使用中容量/総容量」ではない
